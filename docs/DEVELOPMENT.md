# 开发说明

## 环境与命令

初版在 Windows、Node.js 22.16.0、npm 10.9.2 下完成构建与测试。依赖锁定于 package-lock.json。

```powershell
npm ci
npm run dev
```

默认本地地址为 http://127.0.0.1:5173/，以终端实际输出为准。服务器仅监听本机。Ctrl+C 停止。

```powershell
npm test           # 模拟核心与 IndexedDB 替身测试
npm run typecheck  # TypeScript 类型检查
npm run build      # 类型检查 + 生产构建，输出 dist/
npm run preview    # 本地预览生产构建
```

测试使用 Node 的 TypeScript 类型擦除功能，Node 22.16 会打印实验性提示；当前测试已通过。测试不依赖浏览器，也不等同于浏览器验收。

## 状态推进约定

1. createGame 创建初始状态。
2. choose 执行选择；投入任务通过 submitPlan 校验方案，两者产生 pending。
3. 立即保存 pending 状态；此时再次 choose 会被拒绝。
4. 如有飞行，finishFlight 结算一次，清除待飞行标记并保存结果。
5. 失败的 pending.failure 阻止 advance；retry 回到当前事件，并保留 attempts 记录。失败不应用成功效果，重试不重复扣数值。
6. 成功后 advance 进入下一事件或完成篇章，再次保存。

所有引擎操作返回新状态，不直接修改传入对象。随机种子保存在状态内；刷新选择结果页不会重新抽取随机结果。

飞行中刷新从该段起点重新开始，不保存逐帧进度，也不会再次执行先前选择效果。当前不模拟死亡，数值不会自动触发死亡；但失败任务不能直接继续，需要调整后成功。精确时长与阈值是教学参数。

存档使用数据库 if-i-were-a-bird、仓库 saves，当前键为物种 ID 加 :v2。旧版使用的物种 ID 原键不删除。只有事务完成才显示保存成功；失败会提示刷新风险。不兼容的新档也不会自动删除，用户确认后才覆盖对应版本进度。

当前 schema=2，contentVersion=0.2.0。旧版是不同叙事结构，不自动猜测章节对应关系；界面说明旧档保留，新结构从介绍开始。后续改变事件顺序或状态仍需迁移或明确处理。

素材使用独立数据库，重新开始剧情不删除素材。详见 [素材说明](MEDIA.md)。

## 新增内容与物种

- 事件按顺序定义，当前原型为线性章节加局部结果、条件与记忆差异，不是完整分支剧情图。
- 新事件需设置唯一 ID、章节、年龄、地区、季节、画面、选项及可选知识引用。
- 每个事件至少有一个无条件兜底选项，避免状态不足卡死。
- 年龄不得倒退，知识 ID 和章节必须存在。
- 选项可配置简单条件、数值变化、标记、带种子的概率结果，以及可选飞行。
- 错误选项可配置 failure；投入任务配置 budget、channels 与最低／最高条件，并保证约束有解。
- 新物种实现 Species 配置；文字行动不必经过飞行。
- 当前应用入口绑定 swift，尚未提供物种选择器。第二物种在单元测试中验证，正式接入需要修改入口并添加对应场景或行为。
- 新的非飞行动作场景需扩展互动适配接口，当前没有提前构建通用插件系统。

新增或修改数据后运行 npm test 和 npm run build。

## 手工验收清单（尚待执行）

### 桌面流程

- [ ] 首次打开：首页、画面、按钮、文字均正常。
- [ ] 从介绍开始，确认选择后显示结果及数值变化。
- [ ] 错误巢址、准备不足、错误路线和投入方案显示原因，不能跳过；重试与刷新行为正确。
- [ ] 三类投入任务有不同需求，错误总量先提示，满足约束后才继续。
- [ ] 阶段按钮可以读资料，不改变当前进度。
- [ ] 素材馆可选全部阶段，图片、声音、视频可上传、替换、移除与刷新恢复。
- [ ] 重新开始不删除素材，也不覆盖旧版本存档。
- [ ] 在结果页刷新，继续后不重复结算。
- [ ] 初次离巢：进入飞行，方向键有效且不滚动页面。
- [ ] 捕虫、乱流碰撞及结算符合画面反馈。
- [ ] 暂停后计时不变；继续后恢复。
- [ ] 切换窗口或打开手记时暂停，返回后需手动继续。
- [ ] 辅助完成只结算一次，不会重复获得奖励。
- [ ] 飞行中刷新，可重新进入同段飞行并继续故事。
- [ ] 完整走到结尾，查看回忆与解锁知识。
- [ ] 刷新后可恢复已完成结局。
- [ ] 重新开始要求确认；取消后进度不变。
- [ ] 存储权限被禁用时显示明确提示。

### 布局与可访问性

- [ ] 手机竖屏 360/390/430 像素宽无横向溢出，按钮可触达。
- [ ] 手机触控调整高度有效，手指移出后不会持续误操作。
- [ ] 画面覆盖裁切没有隐藏玩家、虫群或必要信息。
- [ ] 键盘可访问选项、对话框和飞行工具。
- [ ] 关闭对话框后焦点位置合理。
- [ ] 减少环境动画生效，不阻断必要互动。
- [ ] 游戏不依赖声音；上传声音和视频不自动播放，有控件。
- [ ] 中档手机和桌面实际测量帧率与载入耗时。

## GitHub Pages 部署

- 源码仓库：https://github.com/cppiod/if-i-were-a-bird
- 演示地址：https://cppiod.github.io/if-i-were-a-bird/
- 工作流：.github/workflows/pages.yml。
- Pages 的发布源为 GitHub Actions。推送 main 或手动运行工作流后，依次安装锁定依赖、运行测试、构建并发布 dist/。
- vite.config.ts 使用相对 base，使入口、样式与懒加载飞行脚本可以在仓库子路径下加载。
- 仓库仅跟踪源码、配置、测试和项目文档；不提交 node_modules/、dist/、环境变量或凭据。
- 若工作流失败，在仓库 Actions 中查看失败步骤；修复后推送或重新运行。不能把工作流已提交当成部署成功。
- 游戏无需服务器和账号。浏览器存档按来源隔离，本地存档不会自动迁移到 GitHub Pages。
- 未来若要自定义域名或使用其他托管，仍可直接发布 dist/；不要将 Vite 开发服务器作为生产服务。
