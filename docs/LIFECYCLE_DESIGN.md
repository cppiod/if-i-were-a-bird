# 八阶段游戏设计 · v0.2.0

本轮按用户结构重排为：**介绍 → 求偶 → 筑巢 → 孵化 → 养育 → 飞行 → 迁徙 → 回家**。

它是一个繁殖与迁徙周期的精选体验。以成鸟为主视角，飞行阶段明确切到幼鸟，再切回成鸟；不把不同年龄、不同个体的经历伪装成同一只鸟突然变换年龄。旧的“孵化开始”版本保留在 Git 历史与原浏览器存档中。

## 当前可玩结构

| 阶段 | 已实现玩法 | 失败与后果 | 下一步可探索 |
|---|---|---|---|
| 介绍 | 形态、环境、食物链、迁徙、文化资料卡；认识环境后进入剧情 | 不考“凭羽色辨雌雄” | 用授权素材增加观察问题 |
| 求偶 | 观察回应与防卫线索，选择接近或退让 | 强行进入被防卫的入口，尝试失败 | 有可靠行为录像后再做叫声辨情境或动作匹配 |
| 筑巢 | 三张巢址卡，比较入口、遮蔽、干扰；选择巢材 | 封堵修缮、无遮蔽平台、长线缠绕方案失败 | 后续增加条件组合与天气变化，不直接按图片猜正确答案 |
| 孵化 | 分配六个共同投入块，平衡照料、觅食与恢复 | 总量不足先提示；满足总量但忽略需要则失败 | 加入日程变化与伴侣状态，仍须保持真实边界 |
| 养育 | 初孵与离巢前两套不同需求；观察羽毛、能力与卫生 | 错误分配或“一律衔走”判断失败 | 有日龄、时长与喂食记录后再加入数据观察 |
| 飞行 | 起飞准备判断 + 30 秒控制高度、捕虫与避乱流 | 在羽毛未充分且强风雨情境中选择立即离巢，准备任务失败 | 后续调整操作手感，以录像打磨体态 |
| 迁徙 | 区域路线选择、补给与同伴线索 + 飞行 | 无补给直线方案、等待同伴代喂方案失败 | 更丰富的风、虫群与路线资源变化 |
| 回家 | 北返补给与飞行，返回后重新检查巢口 | 忽略已知缺食路段或强行进入封闭入口，任务失败 | 跨年巢址与人类行为的更多变化 |

当前有 21 个事件、8 份阶段手记、21 个素材位置和 3 个投入分配任务。阶段按钮随时打开资料，不跳过当前剧情或重写进度。

## 失败机制

- 失败针对当前任务或方案，不等同于鸟必定死亡。
- 失败后显示原因、学习线索与重试按钮，不能直接进入下一事件。
- 失败不应用成功奖励和标记；重试不重复扣能量或身体数值。
- 失败记录保存在 attempts，重试后仍能在回忆里复盘；当前事件的临时失败结果从主历史中移除。
- 失败页刷新后仍是失败页；必须重试并完成任务。
- 阈值与环境卡为教学情境，不表示真实野外失败率。
- 随机事件接口保留，本轮明确的风险题采用可解释的确定性条件。

## 孵化与养育的投入块

投入块表示两只亲鸟共同投入的抽象资源，**不是小时、真实轮换次数、喂食次数或施工／救护指南**。

| 任务 | 预算 | 本情境的最低投入 |
|---|---|---|
| 孵化 | 6 | 巢内照料 3、亲鸟觅食 2、自身恢复 1 |
| 初孵幼雏 | 6 | 觅食带食 3、幼雏照料 2、巢内卫生 1 |
| 离巢前幼鸟 | 6 | 觅食带食 4、卫生 1、亲鸟恢复 1 |

当前是规则与反馈原型，需求已明确提示，主要验证玩家能否理解取舍及阶段变化，不宣称已经具备复杂资源模拟。后续可以在不扩大系统过多的前提下加入可变预算、天气与个体差异。

## 生物学信息的处理

- 雌雄外形相近，不用不同羽色“制造区别”。素材的性别信息需有来源。
- 不把所有叫声与群飞归为求偶；“舞蹈”字段目前保留待补资料。
- 普通雨燕的窝卵数、孵化与离巢参考区间，与北京本地适用性分开说明。
- 每日野外喂食次数尚无本项目核实的北京固定值。救护饲养建议不能代替亲鸟数据。
- 巢内卫生不固定为衔走；普通雨燕研究提供了吞食粪囊的观察。
- 迁徙中“群体合作”的具体分工尚待证据；不添加固定领队、V 字队形省力或接力代喂。
- 艺术中的燕意象与生物学物种鉴定分开，不依据诗画认定北京雨燕。
- 资料卡逐条附来源或标为待补；权威资料的地区与样本边界随条目显示。

## 数据与扩展

- src/content/guide.ts：八阶段资料、来源、素材位置。
- src/content/lifecycle.ts：事件与任务，src/content/swift.ts 保持现有导出入口。
- src/core/types.ts：Failure、AllocationTask 等通用类型。
- src/core/engine.ts：choose、submitPlan、retry、advance 的状态约束。
- src/core/media.ts 与 src/ui/media.ts：持久化、格式检查、公开清单及上传预览。

新增物种可复用事件、条件、失败、投入任务、飞行与素材位置的思路，但当前 UI 的阶段资料仍绑定北京雨燕，尚未做成多物种选择器。不能承诺填完配置就自动完成所有鸟的独特行为。

## 验证范围

自动测试覆盖成功路径、每个错误选项、失败重试、投入约束、刷新恢复、旧档隔离、素材检查与持久化。浏览器里的布局、选择操作、上传解码、触控和完整手感必须单独核实，结果记录在 PROGRESS.md。
