### 当前实现与最终目标的区别

截至 2026-10-25，已实现六章 20 个事件、共用飞行互动、本地存档、图鉴与回忆。当前为压缩流程原型，未达到 30—45 分钟的正式内容目标；尚无音效，画面为程序插画，尚未完成真实浏览器、移动端与外部试玩验收。第二物种仅通过内部配置测试，不是正式篇章。

已采用 TypeScript、Phaser 3、Vite、原生 HTML/CSS 与 IndexedDB，暂不引入 React。实际完成记录以 [阶段进展](PROGRESS.md) 为准，以下 12 周计划仍用于后续迭代与范围控制。

## 1. 项目愿景

让玩家以鸟的身体与有限感知体验世界，经历出生、成长、迁徙、求偶、筑巢、繁殖、育雏与再次出发，体会鸟生的不易、地理的神奇和鸟的美。

风、昆虫、屋檐、同伴以及人类的距离，应当直接影响行动与后果。玩家通过经历理解鸟类需要什么环境、面对什么威胁，以及人如何与鸟共处。

长期希望覆盖多种鸟类；首版先完成一种。每个后续可玩物种应体现自己的生活方式，而非只更换外形与数值。

参考入口：[1 in 8 Billion](https://1in8b.life/)。借鉴“出生后进入另一种生命”的代入感，不假设已完整体验或复刻其分支机制。

## 2. 约束与成功定义

### 2.1 已确定的约束

- 一人开发。
- 暂不考虑商业化，不以付费、留存和日常任务驱动设计。
- 目标在三个月内完成第一种鸟类与游戏框架。
- 网页游戏，便于打开、分享和持续更新。
- 首个物种按北京雨燕规划；正式实现前确认物种及分类名称。

### 2.2 排期假设

- 以 12 周作为开发周期，每周投入 25—35 小时，合计约 300—420 小时。
- 以上投入量为估算假设，尚未确认；低于此投入时优先削减内容与动作复杂度。
- 首版为 30—45 分钟的完整精选鸟生，可分段保存。
- 采用插画场景、事件选择与轻量飞行互动，不逐日模拟真实一生。
- 桌面浏览器优先，手机完成基本适配；具体设备与浏览器在原型期确定。

### 2.3 首版成功标准

1. 玩家可以从孵化走到完整结尾，中途退出后能恢复进度。
2. 存在具有可理解后果的选择，玩家能解释至少一次环境与生存之间的关系。
3. 能感受到雨燕的空中生活、迁徙、巢址依赖，以及人类行为的影响。
4. 关键生物学内容有来源，艺术化简化与不确定内容有明确记录。
5. 第二鸟种的内部测试内容能复用事件、章节、存档与界面，并允许接入独特行为。
6. 分享链接可直接打开，在目标设备上没有阻断流程的问题。

### 3.1 暂缓事项

- 开放世界、自由探索的连续地理地图。
- 复杂遗传、完整食物链、多代繁衍。
- 实时天气、在线账号、云存档、多人功能。
- 多语言、复杂可视化内容编辑器。
- 独立求偶小游戏、筑巢拼图、孵蛋操作。
- 第二个正式可玩篇章。
- 完整重度生存模式及复杂难度系统。

## 4. 设计原则

1. **先感受，后解释。**先经历食物不足或巢址变化，再按需了解原因。
2. **选择有作用，环境也有力量。**熟练操作不能抹去所有生态风险。
3. **美与困难交替。**给顺风、云海、群鸟、羽色与安静黎明留下时间。
4. **有限感知。**鸟先感受到风、气味、光照和声音；地图与地名属于可选解释层。
5. **失败可理解。**展示线索与因果，避免把不可避免的环境风险归咎于玩家。
6. **每种鸟有独特行为。**新物种至少新增一种值得体验的生活方式。

鸟的主观感受、内心文字和镜头语言是艺术表达，不宣称完整还原动物意识。

## 5. 核心玩法

### 5.1 基本循环

感知环境 → 判断身体需要 → 选择行动 → 经历结果 → 留下记忆 → 进入下一段生活。

示例：空气变冷，低处虫群散去。玩家可留在熟悉区域、跟随鸟群或改变高度。结果影响能量、身体、时间或后续事件，避免设计永远正确的选项。

### 5.2 三种体验

| 体验 | 玩家行为 | 首版实现 |
|---|---|---|
| 生命选择 | 觅食、移动、繁殖投入、避开干扰 | 场景文字与选项 |
| 身体行动 | 捕虫、转向、利用气流、短暂避险 | 共用飞行机制 |
| 安静观察 | 看同伴、听声音、感受光照与地貌 | 可停留场景 |

不预先锁定三者时间比例，样章试玩后调整。

### 5.3 飞行互动

- 侧面或斜侧面视角，鸟持续向前，玩家主要控制高度。
- 每段约 30—60 秒。
- 觅食、迁徙与避险复用输入、移动、碰撞与反馈，仅改变参数和资源。
- 能量与身体状况影响结果；不制作复杂飞行物理。
- 默认允许重试或辅助完成，避免动作难度截断故事。
- 触控方案与具体按键在原型阶段验证。

### 5.4 状态与关系

首版只向玩家突出能量与身体状况。年龄、季节、位置、历史标记属于流程状态，不作为额外管理条。

以翼拍、声音、文字和场景反馈辅助表达状态。伴侣关系与巢址记忆先使用少量状态或标记，不建立复杂社交网络。

### 5.5 时间与重复

- 局部行动：几十秒至数分钟。
- 章节事件：选择后推进相应时间。
- 长途迁徙与非繁殖年份：通过地图、地貌过渡与精选事件压缩。
- 浏览器进入后台时暂停；不因玩家离线惩罚鸟。
- 生命周期年龄与章节顺序分开，禁止默认出生次年必然繁殖。

## 6. 北京雨燕首篇

| 章节 | 内容 | 关键实现 |
|---|---|---|
| 1. 屋檐里的光 | 孵化、等待亲鸟、人类家庭的存在 | 有限感知、少量选择、地方记忆 |
| 2. 第一次展开翅膀 | 成长、准备离巢、进入天空 | 可重试飞行教学 |
| 3. 向远方飞 | 食物、风雨、同伴与南迁 | 事件选择穿插短飞行 |
| 4. 陌生的天空 | 非繁殖期与时间流逝 | 观察、身体状态、精选事件 |
| 5. 回到旧地方 | 跳转至适合繁殖的阶段，寻找巢址与伴侣 | 年龄与季节校验、繁殖投入 |
| 6. 又一个离开的季节 | 育雏结果、地方变化、再次出发 | 结尾与鸟生记录 |

### 6.1 人类家庭的表达

用三次相遇建立联系：雏鸟时听见屋檐外的生活声；离开前巢入口得到保留；成年归来再次认出熟悉地点及其变化。

人的照顾通过减少干扰、保留适宜巢位和维护环境表达，不把抓握、驯化或随意投喂作为主要互动。首版不制作人物动画与复杂对白。

### 6.2 迁徙与地理

- 采用有资料支持的代表性路线及范围，不声称所有个体严格走同一路线。
- 鸟的体验层显示空气、风、水面和地貌；可选地图显示现实地名与季节。
- 首版用少量区域节点与过渡画面，不制作连续世界。
- 不直接把欧洲种群数据套用到北京雨燕。

### 6.3 结局

主结局是完成首次繁殖篇章并再次出发；可有少量提前结束的结果。首版以完整体验优先，不加入无提示的高频随机死亡。

结尾生成鸟生回忆：经过的地区、同伴、巢址、环境变化，以及帮助自己生存的条件。不以寿命与繁殖数量作为唯一评分。

## 7. 科学与保护内容

### 7.1 必须遵守的边界

- 北京雨燕与家燕不能共用全部筑巢、栖息、飞行与迁徙行为。
- 长期空中飞行的证据不等同于已证明每个个体的具体睡眠机制。
- “乌鸦记仇”应落实到具体物种的个体识别、经历记忆与社会学习证据。
- 不把“喜爱亮物”作为所有鸦科鸟类的固定天赋。
- 保护建议按地区和物种审核；国外死亡数量等统计不直接套用到中国。

### 7.2 事实台账格式

实施时，每条关键事实记录：

| 字段 | 说明 |
|---|---|
| 编号与命题 | 单条可核实的事实 |
| 物种／种群 | 精确到适用分类与种群 |
| 地区、季节、年龄 | 适用边界 |
| 来源 | 标题、链接、作者／机构、日期 |
| 证据状态 | 较强证据、存在差异、待确认、艺术表达 |
| 游戏用途 | 关联章节、事件或规则 |
| 简化说明 | 为节奏做了哪些调整 |
| 审核状态 | 待核实、已核实、需修改 |

### 7.3 知识呈现

经历 → 简短解释 → 可选深入阅读。知识条目不强制阻断故事。

交流以鸣声、回应、距离、警戒和行为表示。字幕仅说明大致功能，不声称逐句翻译鸟语。避免鼓励诱拍、播放鸣声、随意投喂或接触野鸟来换取游戏奖励。

## 8. 美术与声音

### 8.1 首版资源重点

- 一幅巢内主场景。
- 一套雨燕轮廓与少量翼拍动画。
- 三套可改变色调、云层和地貌的天空背景。
- 一张简化迁徙地图。
- 少量事件插图与结局画面。

优先打磨巢内、第一次离巢、迁徙与归来四个记忆点。地区差异由地貌剪影、光照、声音与文字共同呈现。

### 8.2 音频与无障碍

优先风、雨、巢内环境和鸟鸣，音乐从简。提供音量设置、文字提示、辅助飞行和减少镜头晃动选项。声音不能成为唯一的必要线索。

素材需维护来源与授权记录，非商业发布也要确认许可。生成或加工素材如有使用，也记录其来源、用途与需人工核对的鸟类形态。

## 9. 技术方案

### 9.1 技术选型建议

- TypeScript：模拟、内容类型和应用逻辑。
- Phaser：2D 场景、动画、输入与飞行互动。
- Vite：开发和构建。
- HTML/CSS：菜单、文字、设置与图鉴。
- React：仅在开发者已熟悉且确实便利时采用，原型期确认。
- IndexedDB：本地存档。
- 静态托管：发布网页；具体服务待确定。

不在首版引入必须在线的后端。依赖版本在实际初始化时核实、锁定。

### 9.2 六个模块

| 模块 | 职责 |
|---|---|
| 模拟状态 | 年龄、季节、位置、能量、身体、历史标记 |
| 章节流程 | 进入条件、完成条件、时间跳转 |
| 事件系统 | 触发条件、文字、选项、后果与后续标记 |
| 鸟种配置 | 基础资料、生命周期参数、章节与能力引用 |
| 互动场景 | 首版飞行，后续可新增其他行为 |
| 存档与图鉴 | 进度持久化、知识解锁与回忆 |

模拟核心不依赖画面帧率和 UI，以便独立验证。UI 显示状态并提交行动，规则统一执行，避免多处直接修改状态。

### 9.3 数据与代码边界

数据保存鸟种说明、资源引用、章节、事件、简单条件与状态变化、地区及资料来源。

代码负责状态推进、事件执行、飞行等具体互动、专属规则、渲染、输入与存档。

条件只支持首版需要的数值比较、标记判断、章节与季节判断。不制作通用脚本语言或复杂编辑器。

事件最小结构：

```text
id
适用鸟种与章节
触发条件
鸟可感知的线索与叙事文字
选项及可用条件
确定性结果／带种子的随机结果
时间与状态变化
历史标记与下一事件
事实来源与简化说明
```

### 9.4 扩展鸟种

鸟种配置允许表达是否迁徙、觅食类型、栖息与巢址类型、繁殖阶段、可用互动及专属规则。

新鸟复用事件、章节、存档与界面；独特行为允许新增代码和资源。框架不承诺所有鸟仅靠填写配置完成。

第 10 周制作第二物种内部测试：占位资源、三个事件、不同的行为配置；至少验证一种非雨燕式的行为差异可以接入。若时间不足，可用简化文字行动验证扩展接口，不制作完整小游戏。

### 9.5 存档与随机

- 关键选择与章节后自动保存。
- 保存版本、内容版本、鸟种、年龄、章节、位置、状态、关系、标记及随机状态。
- 使用带种子的随机，保证问题可复现。
- 定义旧存档迁移策略；不兼容时给出明确提示，禁止静默丢失。
- 导入导出存档作为后续增强，不列为首版必要范围。
- 概率没有数据支持时视为平衡参数，不标成真实生态死亡率。

### 9.6 地理与性能

采用区域节点与路线图。节点保存环境与资源参数，路线保存距离等级、风况与事件引用。

章节资源按需加载。初步目标为中档手机稳定 30 FPS、桌面目标 60 FPS；设备基线在原型期明确。首屏资源尽量控制在压缩后约 5 MB，属于优化目标，不以牺牲核心体验硬性达标。

离线缓存与完整 PWA 能力后置；首版不承诺全部离线可玩。

## 10. 十二周实施计划

| 周次 | 主要工作 | 完成标准 |
|---|---|---|
| 1 | 冻结范围、事实台账、六章梗概 | 每章有开始、关键选择与结束 |

| 3 | 飞行原型 | 觅食、气流、能量反馈可玩 |
| 4 | 巢内到离巢样章 | 8—10 分钟，别人可独立试玩 |
| 5 | 试玩调整，冻结操作与美术规格 | 不再增加核心系统 |
| 6 | 南迁、地图过渡、天气事件 | 前半段流程完整 |
| 7 | 越冬、时间跳转、返回 | 年龄与季节顺序正确 |
| 8 | 配对、巢址、育雏、结尾 | 全流程可玩 |
| 9 | 补资源、音效与科普 | 核心占位资源替换完成 |
| 10 | 第二物种接入验证、必要结构修正 | 内部测试片段复用框架运行 |
| 11 | 外部试玩、理解与平衡修复 | 无口头指导能完成主要流程 |
| 12 | 手机适配、性能、部署与缓冲 | 可分享版本完成验收 |

### 10.1 检查点与削减规则

- 第 4 周：样章体验未成立，优先改节奏和互动，减少事件。
- 第 5 周：冻结核心机制；新想法进入后续清单。
- 第 8 周：必须全流程可玩；未完成的额外机制移出首版。
- 第 10 周后：只修复、适配与校正内容。

超期时依次削减额外插图、事件变体、飞行情境与支线；保留主流程、存档、关键反馈、科学边界和结尾。

## 11. 验证与发布

### 11.1 样章试玩

先找 3—5 名首次玩家观察，再根据需要扩大。记录：能否理解行动、是否形成两难选择、能否理解环境后果、是否愿意停留观看、是否愿意继续。

### 11.2 必要检查

- 生命周期、年龄与季节是否合法。
- 事件是否可达，是否存在卡死和无法结束的分支。
- 选项是否有明显的无条件最优解。
- 存档恢复与随机复现是否一致。
- 飞行输入、辅助模式与移动端布局是否可用。
- 素材许可与关键事实是否可追溯。

自动测试优先覆盖状态、条件执行、章节推进和存档等核心逻辑；场景、美术、可理解性与手感通过实际试玩验证。

### 11.3 发布交付物

- 可打开的游戏链接与可重复构建的源码。

## 12. 后续扩展方向

候选方向包括家燕、具体鸦科物种、林鸟、翠鸟、鸻鹬、猫头鹰与信天翁。此清单只是选题池，尚未承诺制作顺序。
